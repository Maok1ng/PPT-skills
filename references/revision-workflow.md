# 局部修改与版本回退

## 以用户手里的文件为准

每次开始编辑都重新读取用户指定路径，而非假设它仍与上次交付一致。记录源文件指纹、实际页数、目标页标题以及允许修改的范围。用户可能删除、重排或手动编辑过页面；“第 5 页”指当前文件的位置。

保留一份输入快照，在工作区另存输出。输入和输出路径、文件指纹、改动页、简短说明记录在本地版本记录中；不要把用户的绝对路径、课件或聊天原文打包进公开 Skill。

## 将反馈转成有限的改动

| 用户反馈 | 执行范围 |
| --- | --- |
| “第 5 页重做” | 先看第 5 页及前后衔接，重构该页；相邻页仅作参考 |
| “统一风格，主要改封面和尾页颜色” | 以限定范围为准；不顺手重画中间页 |
| “这些框很丑” | 检查边框重量、填充、留白和字体层级；能用对齐或细线分组就不强加卡片 |
| “图太细，保持原风格简化” | 保留现有视觉语言和关键数据关系，移走字段、工具参数等细节，加一两句易讲的说明 |
| “改成可编辑流程图” | 使用独立文字、图形和连接线重建指定图，不把原图放进新文本框假装完成 |
| “恢复图片，其他别改” | 从指定旧版取回对应图片，只替换这些对象 |
| “这一页什么意思” | 先解释，未经要求不直接改页或写新文件 |

“统一”并不总是重新设计整套文件。若用户仅要求局部字体/颜色，保留已有内容、结构、图片和备注。修改讲稿仅限与实际内容变化相对应的页；只调颜色时不重写讲稿。未知团队职责、实现细节和数据单位保持待确认，不凭常识补全。

## 回退的处理

- 以最后被用户接受的版本为锚点。明确撤销刚做的一次修改时，恢复该修改前的状态。
- 用户仍在原文件上继续修改时，不用较早完整文件覆盖这些新改动；只撤销被要求撤销的部分。
- 上一版仍独立保存且未被覆盖时，可直接交付已核对的文件链接。若替换当前工作文件，先保存当前版本再替换。
- 只有多个版本确实无法对应时，才问一个简短的版本问题。不能凭文件名“最终版”或修改时间单独判断。
- 不删除用户版本；被撤回的配色或页面结构不带入下一次修改。

## 局部修改怎么验证

1. 视觉检查改动页：无重叠、缺字、错箭头，图文在投影尺寸可辨认。相邻页只检查衔接，不自动更改。
2. 检查实际对象：文字可选中编辑，连线和形状能独立修改，表格和公式的对象类型符合要求。预览 PNG 只用于检查，不作为可编辑内容交付。
3. 页序不变的局部编辑可运行：

```sh
python3 scripts/verify_pptx_edit.py before.pptx after.pptx --changed-slides 5 --native-slides 5
```

`--native-slides` 只用于整页都要求原生图解的页面；有意保留论文图片的页不要放入该参数。脚本只读文件，检查未改页面 XML、备注、主题/版式及关联媒体；它是保守的结构差异检查，不能替代视觉判断，也不能证明公式数值或结论正确。

4. 如果软件只是重命名对象 ID 或规范化 XML，脚本可能报告差异。检查具体差异后作记录，不能未经检查就声称其他页完全相同。若删页、增页或重排，另建源页到输出页的映射，检查内容与备注对应，并仅更新必要页码；脚本不用于这种情形。
5. 交付一个明确命名的成品链接，简要说修改了什么。不要向用户堆积中间导出、检查日志或多个真假“最终版”。
